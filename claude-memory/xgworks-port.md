Reverse-engineering **Yamaha XGworks V4.0** (`F:\rea\XG4\XGworks.exe`, PE x86, MFC 4.0) to reimplement it for ARM/macOS/web. Driven via the REA (Ghidra) MCP tools and the `reverse-engineer-anything` skill.

**Decoded so far:**
- `.XWS` project format fully reverse-engineered and validated: chunk container `[tag][len BE32][payload]`; `S4WH` header (v4, 101-track pool, block count, 480 PPQN); `S4WB` event streams (SMF-like but notes = NoteOn + 4-byte BE gate, no NoteOff); `S4WT` track records with block placements (`[start BE32][end BE32][block-index BE32]`); fixed schema `S4WH â†’ NĂ—S4WB â†’ 101Ă—S4WT â†’ S4ST`.
- MIDI engine is in `Core32.dll` (not the EXE): `midiOutOpen/ShortMsg/LongMsg`. EXE only enumerates + maps ports.
- Plugin ABI: DLLs export `dllMagic`/`dllInit`/`dllInfo`/`wndOpen`, magic tags `SW10`/`MA61`â€“`MA64`.

**Tooling built (validated against `F:\rea\A Dream of a Dream.XWS` + its `.MID` export):**
- `F:\rea\xws_dump.py` â€” Python codec: dump, `--mid` (XWSâ†’MID, 18 named tracks), `--mid-blocks`, `--import` (MIDâ†’XWS). Round-trips note-identical.
- `F:\rea\xgworks-core\` â€” Rust port of the codec (**M0 DONE**: `cargo test` 6/6 green). No deps, builds for wasm32. Shared core for all 3 platforms. Added `playback_plan()` (merges tracks, notesâ†’on/off via gate, tempo map â†’ `(time_ms, midi bytes)`, accepts XWS or SMF).
- `F:\rea\xgworks-web\` â€” **M1 + M2 DONE** (web player + UI). C-ABI wasm shim (no wasm-bindgen; `xgw_alloc`/`xgw_plan`) + `web/index.html`: Web MIDI player, **track list (mute/solo), piano-roll canvas, moving playhead**.
